# Нормализация атрибутов оборудования по нормативным документам

Сервис приводит значения атрибутов из Excel-таблицы (`Attribute` / `Value`, например `Rated power: 75kW`) к виду, который требует нормативный документ: единицы, точность, допустимые значения из списков, формат записи. Работает через чат: таблицу прикладывают к сообщению, а агент нормализует её, отвечает на вопросы о результате и принимает правки и новые правила.

Что умеет:

- **Нормализация по стандарту.** Каждая ячейка получает значение, пометку «на проверку» (жёлтая заливка в Excel) и пояснение: какой паспорт атрибута сработал, что сделал код, на какое правило документа опирался ответ.
- **Уровни уверенности по доказательствам.** «Высокая» — когда ответ подтверждён фактом, который проверил код (форма из таблицы документа, дословная цитата, пересчёт единиц кодом). Сомнительное уходит в жёлтое с предложенным значением, а не записывается молча.
- **Вопросы о результате.** «Какой item больше всего с ошибками?», «сколько строк про мощность?», «почему в строке 12 так?» — считает код по всему файлу, агент только выбирает инструмент и пересказывает.
- **Правки и правила.** Исправить ячейку; превратить правку в правило стандарта (с предпросмотром и подтверждением); дать правило только на один прогон.
- **Извлечение правил из PDF** стандарта в структурированный вид («паспорта атрибутов») — см. ограничения ниже.

## Стек

Python, FastAPI, LangGraph / LangChain, OpenAI API, pandas, pint (единицы), Babel (числовые форматы); фронтенд — React (create-react-app, Ant Design X).

## Что нужно

- Python 3.12+ (проверено на 3.14)
- Node.js 20+ (проверено на 24)
- Ключ OpenAI API. Модели задаются в `graphs/rag_agent/modules/config.py` (`Settings.chat_model`, `embedding_model`); у ключа должен быть доступ к ним.

## Установка

Бэкенд, из корня репозитория:

```bash
python -m venv .venv
```

Windows (PowerShell):

```bash
.venv\Scripts\activate
```

Linux / macOS:

```bash
source .venv/bin/activate
```

```bash
pip install -r requirements.txt
```

Ключ: скопируйте `.env.example` в `.env` и впишите свой `OPENAI_API_KEY`. Файл `.env` в git не попадает.

Фронтенд:

```bash
cd client
npm install
```

## Запуск

Бэкенд (http://localhost:8000), из корня репозитория с активированным окружением:

```bash
python -m uvicorn graphs.rag_agent.api:app --port 8000
```

Фронтенд (http://localhost:3000), в отдельном терминале:

```bash
cd client
npm start
```

При первом старте бэкенд строит поисковый индекс по правилам документов (эмбеддинги OpenAI) и кладёт его в `graphs/rag_agent/data/input/vector_store_*.json`; следующие запуски берут его оттуда.

## Что попробовать

1. Откройте http://localhost:3000, в списке «Стандарты» выберите FG-07 (или оставьте «все загруженные»).
2. Приложите `graphs/rag_agent/data/input/FG-07_input.xlsx` и напишите «нормализуй». Через минуту-две придёт файл результата: колонка стандарта, колонка «— применено» с пояснением по каждой строке, жёлтые ячейки — то, что сервис предлагает проверить. Сравните с `FG-07_expected_output.xlsx`.
3. Спросите о результате:
   - «какой item больше всего с ошибками?»
   - «покажи жёлтые строки и что с ними»
   - «объясни строку 47»
   - «сколько строк про размер?»
4. Поправьте ячейку («в строке 62 должно быть 0.4 kg») — агент предложит сделать из правки правило стандарта, покажет, что изменится, и сохранит только после вашего «да».
5. Правило на один прогон: «нормализуй ещё раз, и на этот раз все массы пиши в граммах» — появится отдельная колонка, стандарт не меняется.

То же с PQS-STD 330: `pqs_std_330_test_corpus.xlsx` и `pqs_std_330_answer_key.xlsx`.

## Ограничения

- **Извлечение новых документов из PDF у вас не заработает без своей vision-модели.** Страницы читает Qwen3-VL-8B-Instruct на отдельном сервере (адрес в `graphs/structured_documents/modules/config_structured_documents_graph.py`, `VL_url`), плюс нужен Tesseract OCR. В репозитории лежат уже извлечённые результаты, поэтому нормализация работает и без этого.
- Каждый прогон вызывает модель OpenAI на каждую строку: таблица на 100 строк — порядка нескольких сотен вызовов.
- Сохранённые правила пользователя пишутся рядом с извлечёнными данными документа (`user_rules.json`) и остаются только на той машине, где их добавили.

## Устройство (коротко)

- `graphs/structured_documents/` — извлечение: PDF → страницы (VLM) → группы правил по атрибутам → паспорт атрибута (вид значения, единица, формат числа, список допустимых значений, инструкции) → проверка паспорта отдельным вызовом модели.
- `graphs/rag_agent/` — сервис: FastAPI (`api.py`), исполнитель паспортов (`spec_runner.py`: модель выбирает, код пишет — пересчёт единиц, формат числа, список), чат-агент с инструментами (`modules/agent.py`, `modules/toolbox.py`), фоновые задачи, MCP-сервер (`/mcp/`).
- `client/` — чат на React.
- `graphs/rag_agent/eval/` — скрипты замера качества на наборах с правильными ответами.
